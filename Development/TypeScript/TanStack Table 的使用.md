## 无头样式库（Headless UI Library）是什么

“无头”指的是**只提供逻辑与行为，不提供任何预设的 UI 外观（CSS）和固定的 DOM 结构**。通俗来说，它给你一套“大脑”和“骨架”，但“长相”完全由你决定。

以 TanStack Table 为例：
- 它管理了表格的核心逻辑：数据排序、分页、行选择、列宽调整、过滤、分组等。
- 但它不输出 `<table>` 标签，不附带任何样式类，也不规定表头长什么样。
- 你通过它提供的 hooks（如 `useReactTable`）获取状态和操作函数，然后自己渲染 `<table>` 或任意元素（如 div 模拟表格），用任何 CSS、Tailwind、styled-components 等来设计外观。

这种模式被称为“无头 UI”（Headless UI），类似的无头库还有：
- Headless UI、Radix UI（无头组件原语）
- React Table / TanStack Table（无头表格）
- Downshift（无头输入/下拉选择）
- React Hook Form（无头表单逻辑）

## 为什么需要无头样式库

### 1. 完全自由的定制能力
传统 UI 组件库（如 Element UI、Ant Design）自带样式和结构，想要深度定制往往需要覆盖样式、侵入内部实现，费时费力。无头样式库不捆绑任何 CSS，你可以直接写出完全符合设计系统的代码，实现像素级还原。

### 2. 契合现代 CSS 技术栈
如今 Tailwind CSS、CSS Modules、CSS-in-JS 等方案盛行，无头库让你用自己熟悉的样式方案去“装饰”逻辑部分，而不是和库内置的样式打架。

### 3. 避免样式冲突和体积浪费
传统组件库常常会引入全局 CSS 或大量冗余样式。无头库不包含这些，打包体积更小，也不会污染你的全局环境，特别适合对样式可控性要求高的团队。

### 4. 更好的可访问性（a11y）支持
优秀的无头库（如 Radix UI）会在内部处理键盘交互、焦点管理、ARIA 属性等复杂逻辑，同时把渲染交给用户。这样既保证了交互的健壮性，又不牺牲视觉上的灵活性。

### 5. 与设计系统无缝集成
大型项目通常有自己的设计系统或组件规范。无头库提供的是“逻辑层”，你可以把这些逻辑封装成符合内部规范的组件，保证跨项目的一致性和可维护性。

### 6. 逻辑与展示分离，便于测试与维护
业务逻辑独立于 UI，你可以单独测试排序、分页等行为，而不用担心样式干扰；UI 层也因为只负责展示而更简洁。这种分离也简化了重构和升级。

---

**总结**：无头样式库的核心价值在于“保留逻辑的强大，交出视觉的自由”。它适合那些对 UI 有高定制需求、希望保持代码纯净、或者需要与特定设计系统对齐的团队。TanStack Table 正是这种思想在表格场景下的典型代表。
